# Public flight terrain distribution

The current candidate uses `bindOnConnect=true`, `serverIdentity=https://mc.muxigame.com/default`, and format-2 public terrain. `hashedSeed` and `serverFolderKey` must be absent or empty. Format-1 remains supported only for explicit legacy bindings; the old QA-bound release fragment is not a production input.

The existing official HTTPS manifest source, launcher route proxy, join-grant flow and authenticated terminal broker supply the trust boundary. No new credential, private key or account permission is introduced. The launcher records verified manifest provenance, stages only a hash-checked public policy, and passes the exact loopback proxy endpoint and policy digest to its game process. Arbitrary manifest origins, missing existing broker context, and inherited environment values cannot enable binding. This adds no independent transport-authentication guarantee beyond the existing official connection path.

During that connection, the Flight server checks the existing admitted account and actual terrain generator/settings, then returns a nonce-bound, fresh world identity and actual obfuscated DH seed key. The world identity file is public cache metadata, not a credential. The client matches its actual selected/connected endpoint, loaded Flight/DH JARs, DEM, package, dimension and DH wrapper key before import. A private immutable binding records the world/dependency identity. Changed worlds, mismatched dependencies and unbound existing databases are isolated without opening the previously approved public database.

The public archive contains exactly manifest.json and terrain.sqlite. It carries no fixed QA seed, account, address or other world. Live DH SQLite files are never Managed, pruned or overlaid. Before DH opens the target database, a bounded staged copy is flushed and hash/header checked, then atomically linked without replacement. Existing databases and sidecars remain untouched; interrupted pending metadata supports exact-hash recovery. Receipts omit account identifiers, nonces, credentials and raw seeds.

Offline checks: Java binding/import tests 25 assertions; actual launcher downloader/importer/context regression 37 assertions; pack builder legacy and neutral-artifact tests pass. These caught and fixed a JsonSerializerOptions context-reuse exception. Core, Protocol and Launcher compile with the existing CrashReport.cs IL2026 warning. Portable SDK: build/flight-dotnet-sdk (9.0.318).

MC acceptance remains required: normal first connection, reconnect, wrong server/world, changed-seed native terrain comparison, DH import timing and normal room0 lifecycle/combat. Direct login into the Flight dimension before the proof arrives fails closed into an isolated cache; practical reconnect behavior must be checked. No production deployment or client publication is authorized by these offline results.
