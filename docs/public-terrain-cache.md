# Public flight terrain distribution

The launcher now accepts `publicTerrainCaches` in the pack manifest. The pack builder copies this field from packspec and validates the actual source files before producing a publishable manifest. `SyncEngine` downloads the archive as a required Managed file; `LaunchPipeline.PrepareAsync` verifies and imports it before Minecraft starts, including when SkipVerify is enabled. The live DH SQLite database is never Managed or pruned.

A cache entry requires `packagePath`, `packageSha256`, `generatorPath`, `generatorSha256`, `dhPath`, `dhSha256`, `demSha256`, `dimension`, `metresPerBlock`, `roomSpacing`, `roomSlot`, `hashedSeed`, and `serverFolderKey`. Paths refer to actual installed files. Currently only `muxi_minigames:flight_iwo_half`, 2 metres/block, spacing 49152 and slot 0 are accepted. Package/generator/DH must be nonoptional Managed files in packspec. Archive contents are exactly manifest.json and terrain.sqlite; the archive, DEM in the generator JAR, dependency JARs and extracted database are hash-bound.

The publisher must confirm the actual server-sent DH server key and level key from the target deployment. Do not guess from a display name, connection address or server.properties: an existing world can have a different seed. The level directory is `<hashedSeed>@muxi_minigames@@flight_iwo_half`. The first offline release input still has the verified QA seed key `h1qnkdsfn63tg`; the intentionally empty serverFolderKey prevents accidental publication. If the target key differs, terrain compatibility and the new binding must be separately verified before generating a target-specific package. Do not edit the key only in packspec: the package/context check will reject it.

The installer rejects unsafe paths, links/junctions, unsupported scale/room, mismatched versions, unexpected ZIP members and oversized database extraction. It stages beside the destination, flushes, checks SHA-256 and SQLite header, then renames without replacement. Existing databases and WAL/SHM/journal sidecars are preserved, with a log result. It never merges or replaces player caches. Install is only in the normal prelaunch path, not while Minecraft is running.

Offline verification: `client/tests/public-terrain-cache/run.py` compiles a small runner against the actual Core/Protocol DLLs. It exercises the real downloader with an in-memory HTTP response and the real importer, including malformed identities, old QA-bound packages, player-cache preservation and extra ZIP entries. The runner uses unique build fixtures. `server/tests/test_public_terrain.py` exercises the real pack builder with formal release inputs; existing manifest-builder tests also pass.

Build requires .NET 9 SDK. In the current workspace the system SDK was absent; a portable Microsoft SDK 9.0.318 was placed under build/flight-dotnet-sdk without changing the system installation. The launcher build passes with one pre-existing CrashReport.cs IL2026 warning. This does not claim MC/GUI or production acceptance.
