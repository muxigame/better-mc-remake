# 有主人的女仆/模块化傀儡：强敌半效兼容补丁

独立小模组 `muxi-champion-companions-1.0.3.jar`，不重编或覆盖 muxi-game-core 的任务功能在制代码。
绑定 Champions 21.1.1.7 与当前核心的 `ChampionRules`；升级这些实现时必须重新测试。


## 女仆胶片复活保留强敌状态

1.0.4 修复车万女仆“死亡生成胶片后，胶片复活丢失 Champions 阶级/词缀”的问题。
女仆原生胶片会保存自己的实体 NBT，但 Champions 的状态保存在独立 NeoForge attachment 中，
而 `ItemFilm.filmToMaid` 只调用女仆的 `readAdditionalSaveData`，因此 attachment 不会被原生恢复。

补丁监听车万女仆 1.5.3 已提供的 `MaidAndItemTransformEvent.ToItem/ToMaid`：

- 转成胶片时把原强敌阶级 ID、每个词缀 ID/强度/运行数据、单次抽取标记和迁移标记写入胶片自己的 maid data。
- 从胶片复活后，等女仆原生 NBT（包括主人）恢复并进入世界，再按原阶级和原词缀重建 Champions。
- 不重新进行 33% 抽取，不重新抽阶级，也不会因为复活产生额外一次中奖机会。
- 原本不是强敌但已经抽取失败的女仆，同样保留“已抽过”状态，复活后不会重抽。
- 若保存的阶级/词缀在未来模组版本中不存在，恢复会保持 pending，而不会静默退化成一次新的随机抽取。

强敌快照编解码在隔离服使用真实 Champions 运行逻辑验证；事件桥接直接针对当前
`touhoulittlemaid-1.5.3-neoforge+mc1.21.1.jar` 的真实事件 API 编译。测试环境直接加载完整女仆模组时，
其自身 LLM HttpClient 会因隔离环境 loopback 限制启动失败，因此不通过修改网络环境来绕过该限制。

## 资格和抽取

仅 `OwnableEntity` 且主人 UUID 非空的以下 ID 获得旧“只允许敌对生物”规则的例外：

- `touhou_little_maid:maid`
- `modulargolems:metal_golem`、`modulargolems:humanoid_golem`、`modulargolems:dog_golem`

不整体允许中立生物，也不允许所有宠物；牛、鱼、村民、猫、狼等仍遵守旧规则。
主人不必在线。自然生成时的原有敌对生物资格不变。

自然强敌仍读取 `config/champions-server.toml` 的 `spawnChance = 0.1`。
有主人的上述四类随从单独读取 `config/muxi-champion-companions-server.toml`：

```toml
[spawning]
    ownedCompanionChance = 0.33
```

1.0.3 将随从默认抽取概率从共用的 10% 改为独立的 33%；只替换本次随从抽取的概率读取，不修改全局 `ChampionsConfig.spawnChance`。
沿用阶级抽取、信标保护和半效规则，不保证每个随从都是强敌。仍受原有资格、数据与信标条件约束；在有效信标保护范围内不会生成强敌。
自然生物的阶级权重保持 `50 / 25 / 15 / 8 / 2`，满足生成条件时的单次绝对概率为 `5% / 2.5% / 1.5% / 0.8% / 0.2%`；玩家制作/召唤的四类有主随从改为 `50 / 25 / 15 / 7 / 3`，对应 `16.5% / 8.25% / 4.95% / 2.31% / 0.99%`，合计仍为 `33%`。
处理召唤/驯服/制造过程中“加入世界以后才设置主人”的情形：每秒在单个已加载实体的 tick 回调检查一次资格，不扫描整个世界。
首次符合条件时抽一次；成功/失败均写入实体持久标记，普通重登和区块加载不会无限重抽。
本次不修改 `rolled_v1` 标记版本，调高概率不会给已经抽取失败的旧实体额外机会；尚未抽取的旧随从和新制作/召唤的随从使用新的概率。
旧的已绑定随从首次加载后同样有一次机会。标记按存档实体保存；模组若拆解后创建了一个全新的实体，则是新的抽取对象，不声称能拦截所有拆解重造流程。
已经是强敌的旧随从在首次处理时按原阶级重建一次，只迁移属性/词缀规则，不重新抽阶级；原有非安全词缀替换为安全词缀，其他已有词缀保留。通过持久版本标记避免每次加载反复重建，迁移保留当时的剩余生命比例。

## 半效的准确含义

**只减半 Champions 新增的增益，不减半本体属性，不再次减半傀儡之前已经调整过的基础数值。**

阶级增加的攻击、护甲等属性修饰符数值乘 0.5。生命采用相配套的 V3 脚本，额外生命乘 0.5。
同一基准 H，传奇敌人为 `H + B(H)`，传奇随从为 `H + B(H)/2`。

| 词缀 | 随从半效实现 |
|---|---|
| 急速 | 额外移速属性数值减半 |
| 活力 | 每次回血量减半，冷却与闲置倍率不再额外砍半 |
| 抑制、适应 | 实际免去的伤害减半，包括达到上限时；不把剩余承伤误乘 0.5 |
| 保护 | 护盾激活期间由完全阻挡改为阻挡 50% 伤害；不靠降低切换概率冒充半效 |
| 反射 | 反射伤害减半，不反伤主人/盟友 |
| 爆震 | 击退力度和附带减速持续时间各自减半，不作用于主人/盟友 |
| 瘫痪、创伤 | 触发概率减半，单次效果及持续时间保留，不再二次减半变成四分之一 |

只给随从分配上述九种可明确缩减的词缀。其它词缀被替换为未重复的安全词缀，保留已抽到的词缀数量和强度。
这样避免范围伤害、寄生召唤和免疫等在友方语义下不可准确减半或易误伤的行为。
**敌人的词缀池、强度、处理逻辑均不变**。概率/控制类没有“整体战斗力精确 50%”的保证。

不修改战利品表、已有掉落减半配置、经验或自然强敌生成概率；只独立调整上述玩家随从的抽取概率与阶级权重。新增资格沿用 Champions 原有后续逻辑。
服务端当前核心 1.4.0、干净源核心 1.3.0 中涉及强敌资格/清理的三个类字节完全一致；兼容模组允许两者，不借此升级或替换用户的核心 JAR。

## 生命曲线 V3

`B(H) = 0.625*H + 80.15625*H/(H+13.75)`

`新上限 = H + 阶级权重 * B(H) * (随从 ? 0.5 : 1)`

五阶权重：`0.125 / 0.3125 / 0.625 / 1 / 1.5`。
传奇敌人精确锚点 `10→50、20→80、200→400`；传奇随从 `10→30、20→50、200→300`。
H 是去掉强敌生命修正后的实际生命上限，包含其它模组既有修正，不是受伤后的剩余血量。
原强敌生命修饰符被替换而不是叠加；迁移保留剩余生命比例。

## 实际发现并修复的兼容问题

安装的 Champions JAR 包含 KubeJS 插件类和 Java 事件桥，但缺失 `kubejs.plugins.txt`，导致此前的 `ChampionsEvents` 在脚本运行时不存在。
本补丁提供发现入口，复用上游插件类，不重复注册 Java 事件回调。
生命脚本同时兼容 Rhino 将 `Entity.level` 与 Java record 组件暴露成属性而不是方法的行为。
另将 UUID 与重载的 `removeModifier` 调用经明确类型的 Java 接口执行，避免脚本引擎的映射/重载歧义；函数内采用 Rhino 稳定支持的局部声明方式。
原傀儡战斗减半脚本有同一个重载歧义，本次只修正接口调用及局部声明，保留全部 0.5 数值和作用属性。两份脚本必须和兼容 JAR 一起部署/回滚。
这两点不是 Node 模拟测试/纯语法检查能证明的，因此增加了隔离 Minecraft 启动测试。

## 构建、测试、部署

`python build_companions.py` 只构建本补丁，依赖仅参与编译，不打包第三方代码。

`python run_smoke.py` 用现有运行库启动隔离的临时测试服，关闭局域网广播；测试专用模组跳过 TCP 监听，因此即使本机无法再创建 loopback selector 也不会占用端口。测试仍使用真实 Champions/KubeJS/Core 代码和合成 OwnableEntity，结束后停服，不读取/复制正式世界、玩家或凭据。
测试包含所有九种真实词缀处理、旧中立限制、半效属性、生命锚点、后设置主人和存档标记；还加载真实生产傀儡脚本，用测试属性接口验证既有战斗减半与新强敌增益的组合。测试实体和傀儡属性接口是测试桩，它不代替正式整合包里真实女仆/傀儡召唤操作的验收。
1.0.3 以确定随机种子实际调用变换后的 `ChampionSpawnHandler.trySpawn`，确认四种随从使用 33%、野生僵尸仍使用 10%、随从阶级权重为 `50/25/15/7/3`、自然敌人为 `50/25/15/8/2`、未绑定实体仍不符合资格，且提高配置不会重抽已有失败实体。

`python deploy.py` 仅检查；加 `--apply` 部署测试通过的相同字节到服务端与干净源。
部署前自动备份，检查并发改动，验证其他脚本/掉落/枪械/傀儡配置/核心 JAR/发布规则未变。
不重启正式服务器，不发布 OSS。新增 JAR 必须正常重启后才加载。
升级时备份并移除两端旧的兼容补丁 JAR，不能同时保留两版；部署脚本只删除明确的旧补丁版本，不碰其他模组。

仅回退 1.0.3 阶级分布更新时：恢复上一版 JAR，并保留独立随从概率为 33%；生命与傀儡脚本本次未改，无需回退到更早版本。

## 回滚

必须成组恢复归档的旧生命脚本和傀儡战斗脚本，并移除两端新增兼容 JAR；不能只删 JAR 留下依赖它的脚本。
核心恢复旧资格规则后会在加载时清除不再符合资格的友方强敌数据及其 Champions 属性；敌人生命上限随恢复的脚本重新计算，受伤比例仍保留。
未加载区块中的实体要等加载时处理。此前额外掉落减半及傀儡/枪械配置无需回滚。
