# Champions 生命曲线 V3（敌人全效、指定有主随从半效）

此版本替代此前 V1/V2，不再使用旧的平方根或幂函数曲线。

## 当前公式

强化前生命上限为 H，去掉 Champions 自己的旧生命修正，但保留其他模组的既有属性修正。

`B(H) = 0.625 × H + 80.15625 × H / (H + 13.75)`

`新上限 = H + 阶级权重 × B(H) × 效果系数`

阶级权重：`0.125 / 0.3125 / 0.625 / 1 / 1.5`。敌人效果系数 1；符合补丁白名单且主人 UUID 非空的女仆/模块化傀儡效果系数 0.5。

| 阶级 | H=10 | H=20 | H=200 |
|---|---:|---:|---:|
| 普通强敌 | 15 | 27.5 | 225 |
| 稀有 | 22.5 | 38.75 | 262.5 |
| 精英 | 35 | 57.5 | 325 |
| 传奇 | 50 | 80 | 400 |
| 终极 | 70 | 110 | 500 |

上述是敌人数值。传奇随从同样基准下为 `10→30、20→50、200→300`，减半的是额外生命，不是最后总生命。

原有苦力怕排除、非强敌排除、生命属性上限和其他模组修饰符保持原样。读取现有实体时替换同 ID 的永久修饰符，不和旧规则叠加，保留处理时的剩余生命比例。健康状态不是公式输入，不会越打上限越变化。

## 必需的配套补丁

本脚本依赖 `../champions-companions` 的独立兼容模组；不能只发布脚本不发布 JAR。

配套补丁还修复本机 Champions JAR 缺少 KubeJS 插件发现入口的问题。旧脚本的 Node 模拟和 Rhino 语法校验不能证明事件可用；本次加入真实隔离服务器测试，另修复 Rhino 对 Entity.level、UUID 和 Java record 组件的方法/属性映射差异。

## 验证与部署

`node test_champions_health.cjs` 检查五阶曲线、三个精确目标、前两版存档迁移、伤势比例、未知阶级、无主/非目标、属性上下限与无叠加。

`python apply_champions_health.py` 默认仍仅运行离线检查。不应单独加 --apply 安装此版本，应使用 `../champions-companions/deploy.py --apply` 成组部署经过隔离测试的相同 JAR 与脚本。

`../champions-companions/run_smoke.py` 验证真实 Champions/KubeJS/Core 事件调用、生命数值和词缀。测试用模拟有主实体，不是对正式世界的玩家随从进行操作。

## 回滚

完整回滚此次改动应成组恢复归档旧脚本并移除新增兼容 JAR。旧的 V2 脚本原先有上文所述事件入口问题，恢复它不是一项已通过真实游戏测试的修复方案。

若仅恢复原版生命规则且保留兼容模组，可用 `apply_champions_health.py --restore-vanilla --apply`，重启后加载的实体恢复原生 .35×阶级/5 规则（符合随从白名单的额外增益仍减半）。未加载区块需要加载后处理。

不要仅删除脚本并认为存档内的永久生命修饰符会自动消失；不会。

更完整的随从白名单、半效定义、测试边界和备份信息见 `../champions-companions/README.md`。
